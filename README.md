# dsh-closure-ledger

**闭合账本。** 它让「我查过了」这句话变得可对账。

## 它解决什么

我每天产出大量**判断**：

- 「这 5 个 dirty 文件是主人的仓，不归我提交」
- 「这条测试债是期望写错，不是代码错」
- 「这条路走不通，因为 X」

这些判断**只存在于当轮汇报里**。会话一过就蒸发。后果有两个：

1. **下次重查** —— 同样的面，同样的取证，白干一遍。
2. **更糟：干净的区域和从未访问的区域，读起来一模一样。**

第二条是我的直接立项理由。Strix 的 `counterevidence.md` 把它说得比我好：

> 只记录发现的扫描，无法告诉读者什么被审过并澄清了，
> 这让每个干净区域与未访问区域无法区分。

## 硬机制：判「清白」必须指名控制

整个插件**只有一处强制**，但它很重要：

**记 `cleared` 时，`control` 必填，且要过两道校验。**

1. **位置指针**：必须含 `path/to/file.ts:42`、`observed@<实测到的行为>` 或 `test:<测试名>` 之一。没位置的清白理由，别人照着复核不了。
2. **空话黑名单**：`框架会转义`、`ORM 处理了`、`一般不会`、`默认安全`、`自动转义` 等短语一律拒收。

设计取舍写在这里，因为它是刻意的：**宁可误伤，不可放过。**

- 误伤的代价 = 降级记 `checked`（「查了、指不出具体控制」）—— **这是诚实的**，不造成谎报。
- 放过的代价 = 一句空话被当成清白证据留存，将来被我和别人引用。

两者不对称。所以**带位置指针的空话仍然被拒**（空话加位置只是包装）。

### 指不出控制不是失败

五态里没有「必须清白」这一说：

| 裁决 | 含义 | 要 control 吗 |
|---|---|---|
| `confirmed` | 已证实有问题 | 否 |
| `cleared` | 已排除 | **是** |
| `proof_gap` | 既不能证实也不能排除 | 否 |
| `checked` | 查过、没发现、指不出具体控制 | 否 |
| `na` | 不适用 | 否 |

`proof_gap` 和 `checked` 是**一等公民**，不是失败的兜底。「填不出凭什么就说不知道」比「编一个听起来合理的理由」有价值得多。

## 五个工具

| 工具 | 作用 |
|---|---|
| `closure_record` | 记一条：面 + 裁决 + 凭什么 + 覆盖范围 |
| `closure_list` | 动手前查「这个面我以前判过吗」——避免重查，也避免沿用过期结论 |
| `closure_revise` | 改判。**why 必填**；旧裁决进 history，不被抹掉 |
| `closure_gaps` | 缺口清单：所有 `proof_gap` + 所有超期未复核的 `cleared` |
| `closure_summary` | 总览，且显式声明「这个数只覆盖被记录过的面」 |

## 与既有载体的分工（防平行真源）

| 载体 | 管什么 |
|---|---|
| `dsh-agent-taskboard` | 要做的活（终态出板归档） |
| `dsh-longhorizon` | 未完成项（还欠什么） |
| `dsh-evidence-router` | **一次任务内**的证据够不够（会话级，关闭即终结） |
| **本插件** | **已终结的判断**，且要能被后来者反驳与修正（长期，条目常驻） |

四者语义不重叠。本插件的 `proof_gap` 可人工转成 taskboard 项——这是接口，不是重复。

## 设计要点

- **写路径纪律搬自 `dsh-longhorizon/src/store.ts`**：严格读 + 原子写（tmp→rename）+ 留痕。**读路径可以退化，写路径绝不可以**——损坏的账本被一次写入覆盖成「只有刚写的那条」= 静默数据销毁。
- **整库畸形 vs 单条畸形的代价不对称**：误丢单条少一条读数，误丢整库不可逆。故全部条目畸形且原始非空时**抛错**，不返回空账本。
- **同一个面重复 `record` 会拒收**并指向 `revise`——防「用新条目覆盖旧判断」把「谁改过、为什么改」抹掉。
- **陈旧机制**：`cleared` 超过 30 天（可配）未复核就进缺口清单。代码会变，清白会过期。
- **不做提示词注入**：本插件不占每轮上下文。它是「要对账时主动查」的工具，不是贴身提醒——贴身提醒的职责归 `dsh-longhorizon`。

## 生效判据与回退

**生效判据**（三条都要）：

1. `lib/index.js` 的 mtime 晚于构建命令执行时间。
2. 重启后 `closure_summary` 能调通，返回「账本空」而不是「未知工具」。
3. 实测一次 **拒收**：`closure_record` 送 `verdict=cleared` 且 `control="框架会转义，安全"`，必须返回拒收且理由为 `generic_trust`。

第 3 条是关键——**一个只会在正确输入上通过的校验器等于没有校验器**。

**回退**：`plugin_unmount dsh-closure-ledger`。账本文件在 `<DSH_HOME>/closure-ledger/ledger.json`，卸载不动数据；重装即接回。

## 测试

```
node --test "tests/*.test.mjs"   # 40 passed
```

测试重点不是「代码跑不跑得动」，是**判据拦不拦得住**：该拒的拒了、该过的过了，外加那条故意选的方向（带位置的空话仍被拒）。
